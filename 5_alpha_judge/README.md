# AlphaJudge inputs

AlphaJudge uses the run directory name as the job name, so every run dir is
named after the spreadsheet `Complex` column (`P69B_SSP1`, `Pip1_EpiC2B`, ...).
Chain A = hydrolase, chain B = effector in every run.

All current runs use the mature, AFM-matched sequences (P69B 635 aa, Pip1 219 aa,
Ecp36 without FLAG). The prodomain runs (P69B 723 aa / Pip1 316 aa: Boltz-2
`2_boltz/boltz_results`, AF3 cluster `3_af3/cluster/outputs`, and their summaries)
were deleted on 2026-11-10; their inputs remain in git history.

| Method | Run dirs | Summary |
|---|---|---|
| Boltz-2 | `2_boltz/boltz_results_afm_matched/boltz_results_<Complex>/predictions/<Complex>` | `boltz2_matched_summary.csv` |
| Boltz-2 reduced-DB | `2_boltz/boltz_results_reduced/...` (MSAs from the AF3 pipeline) | `boltz2_reduced_summary.csv` |
| AF3 cluster | `3_af3/cluster/outputs_afm_matched/<Complex>/<Complex>` | `af3_matched_summary.csv` |
| AF3 cluster full-DB | `3_af3/cluster/outputs_fulldb/<Complex>` (AFM full_dbs MSAs) | `af3_fulldb_summary.csv` |
| AF3 server | `3_af3/server/<Complex>` | `af3_server_summary.csv` |
| AFM full-DB | `4_afm/afm_matched/<Complex>` (25 predictions each) | `afm_matched_summary.csv` |
| AFM reduced-DB | `4_afm/afm_matched_reduced/<Complex>` (25 predictions each) | `afm_reduced_summary.csv` |

Each was scored with
`alphajudge -r <run dirs> --models_to_analyse all --force_recompute -o 5_alpha_judge/<summary> --aggregate_report 5_alpha_judge/<summary stem>_report.pdf`.

The run directories are not in git; the structures are on Zenodo (`8_zenodo/`).
The summary CSVs are committed; the per-run reports (`*_report.pdf`) and logs are
regenerated by the command above and not tracked.

## What was changed

- `standardise_names.py`: renames AF3 cluster/server and AFM run dirs (and
  prefixed files) to canonical names. AF3 server downloads were restructured
  into the local AF3 layout (`seed-<seed>_sample-<n>/…_model.cif`,
  `…_confidences.json` ← `full_data_n.json`, `…_summary_confidences.json`) plus
  a generated `<Complex>_ranking_scores.csv`. Server `model_n` (server rank n,
  single seed) became `sample-n`. Server ranking scores are rounded to 2 dp, so
  ties keep server order. Every move is in `rename_log.tsv`.
- `convert_afm_pickles.py`: the AFM result pickles held old-jax DeviceArrays
  that no local env can unpickle. They were rewritten as plain numpy (same
  values) under the same name, with originals in `<run>/original_jax_pkls/`
  (~5 GB; delete once happy).
- AFM `relaxed_/unrelaxed_model_*.pdb.gz` were decompressed alongside (AlphaJudge
  does not read `.pdb.gz`).

## Caveats for interpretation

- AF3 server P69B is 634 aa (`SLHTTH…`) in eight runs and 635 aa in P69B_EpiC2B;
  every other method uses 635 aa (`LSLHTT…`).
- Other `4_afm/*` dirs (`Solyc08g079870…`, `mature*`) have no result pickles or
  PAE, so they cannot be scored. The `Solyc…KAH3648627.1` Ecp36 carries a FLAG tag.

## Cross-method summary

`python 5_alpha_judge/consensus_summary.py` reads the AFM-matched summaries (AFM
full-DB, AF3 server, AF3 cluster, Boltz-2) and writes `consensus_summary_matched.csv`:
the top-ranked model per complex per method, with tiers (High: ipSAE ≥ 0.5 and meta ≥ 0.6 in every method; Mixed: at
least one method with ipSAE ≥ 0.3; Low: otherwise), ranked by mean meta score.

## AFM-matched reruns (2026-11-06)

Boltz-2 and AF3 cluster were re-run on the AFM sequences
(`1_sequence_processing/afm_matched/`; P69B 635 aa mature `LSLHTT…`, Pip1
mature, Ecp36 without AFM's FLAG+linker). AF3 matched dirs were renamed to
canonical names by `standardise_names.py` (same logic as `outputs/`).

```bash
alphajudge -r 2_boltz/boltz_results_afm_matched   --models_to_analyse all --force_recompute -o 5_alpha_judge/boltz2_matched_summary.csv --aggregate_report 5_alpha_judge/boltz2_matched_report.pdf
alphajudge -r 3_af3/cluster/outputs_afm_matched   --models_to_analyse all --force_recompute -o 5_alpha_judge/af3_matched_summary.csv    --aggregate_report 5_alpha_judge/af3_matched_report.pdf
python 5_alpha_judge/consensus_summary.py --matched   # -> consensus_summary_matched.csv
```

`--models_to_analyse all` is needed: the default scores only the best model.

## AFM-matched cluster run (2026-11-09)

All ten complexes re-run with AFM on ARC (`4_afm_cluster/`; AF 2.3.1, multimer
v3, `full_dbs`, MSAs computed per complex, 5 models × 5 seeds, base seed
20261108, all 25 relaxed). Only `relaxed_*.pdb`, gzipped `result_*.pkl.gz` and
the small JSONs were copied to `4_afm/afm_matched/<Complex>`. The pickles hold
jax arrays, so they were converted first (originals in
`<Complex>/original_jax_pkls/`, ~45 GB; delete once happy):

```bash
python 5_alpha_judge/convert_afm_pickles.py 4_afm/afm_matched/*/
alphajudge -r 4_afm/afm_matched --models_to_analyse all --force_recompute -o 5_alpha_judge/afm_matched_summary.csv --aggregate_report 5_alpha_judge/afm_matched_report.pdf
python 5_alpha_judge/consensus_summary.py --matched
```

`consensus_summary.py --matched` now reads `afm_matched_summary.csv`, so every
complex has all four methods. The cluster's AF 2.3.1 module (CUDA 11.7) crashes
on H100s at the first inference step, so AFM jobs must request Ampere GPUs.
